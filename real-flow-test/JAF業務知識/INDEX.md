# JAF業務知識

JAF RS プロジェクトの業務知識の正本。仕様の理解・RV・テスト実行・結果判定に使用する。

## 段階的・オンデマンド読取の原則（全件一括読取の禁止）

1. **開始時の最小読取**：どの工程でも、最初は本 `INDEX.md` と `共通/仕様書の表記・改訂規則.md` の 2 ファイルのみを読む。知識庫内の全ファイルを無差別に一括列挙・連続読取しない。
2. **工程・段階別の選択読取**：
   - **仕様書レビュー（`rv-reviewer`）**：仕様書の表紙・対象機能・画面 ID を確認し、下表から対象範囲に該当する文書のみを選択して読む。
   - **テスト実行（`execution-plan-generator`）**：
     - **実行登録前（`RUNNING` 登録まで）**：上記の最小 2 ファイルに加え、試験対象の入口・主画面文書（例：受付起動は `業務/受付アプリの起動・終了.md`、救援依頼入力 `JAFRSAO02001` は `業務/救援依頼入力.md`・`既知の注意事項/確認済みの制約.md`）のみを読み、先に `executionBasis` 検証と `test_execution` の `RUNNING` 登録を完了する。
     - **MCP 操作中（ケース実行時）**：子画面遷移や個別業務機能のケースを実際に操作する時点で、下表から該当する文書のみをオンデマンドで追加読取し、同一実行内で再利用する。
   - **結果判定（`result-judge-triage`）**：実操作が行われたケースの期待条件照合や失敗原因の切り分けに必要な対象画面・機能の文書のみを読む。共通の前置阻害等で未実行（`notRun`）となったケース群の整理では、無関係な業務詳細文書を追加読取しない。

## 適用と保守の原則

- 未収録を機能の不存在と解釈せず、テスト範囲も自動で広げない。
- 業務判断は本知識庫、試験対象・入力・期待結果はテスト仕様書に従う。矛盾は RV で指摘し、確定済みの試験内容は実行中に黙って変更しない。環境条件と実行結果は実測で確認する。
- 文書は業務・画面ごとに該当ディレクトリへ追加し、改訂時は上表の対応を更新する。
