# 受付アプリの復旧・点滅支部設定

## 前回の受付入力の復旧

`t_uketsuke_lock` を `user_cd`、`term_no`、`subsystem_id='1'` で取得し、更新日時の降順で先頭の受付番号を復旧対象にする。該当なしは内部値 `-1` とし、通常の救援依頼入力画面を表示する。

該当ありでは、取得した受付番号リストに対する `t_uketsuke.nyuryokutyu_flg` を `0` に更新し、リストの各番号について `ReleaseLock` を呼ぶ。復旧案内 `JAFRSAIC00014` を表示し、先頭の受付番号と `IsRecovered=true` を入力画面へ渡す。

**復旧表示するのは先頭の 1 件、更新・ロック解除の対象は取得したリスト**。複数残存ケースを 1 件の更新と同一視しない。これはアプリが行う復旧動作であり、テスト Agent による DB ロックの直接削除を許可する説明ではない。

## 点滅支部設定

起動時は当該端末・アプリの `t_blink_shibu_setting` を削除し、ログインユーザーの本部に対応する集約地方本部から対象支部を取得・登録する。

| ログイン本部 | 対象とする本部 |
| --- | --- |
| 1 関東 / 6 東北 / 8 北海道 | 1・6・8 |
| 2 中部 | 2 |
| 3 関西 / 4 中国 / 7 四国 | 3・4・7 |
| 5 九州 | 5 |

対象支部は `m_rs_shibu_name_info` と `m_bumon_dsp_info`（`bumon_cls='1'`）から取得する。支部リストが空なら INSERT は 0 回。本部対応が決まらない初回起動経路では、既存設定の削除後に登録処理を終了する。

終了時は当該端末・アプリの設定を削除する。アプリ ID は SQL が `m_code_app_cd` の `UKT` に対応する値から求めるため、`appli_id` に文字列 `UKT` がそのまま保存されるとは限らない。

## DB 確認の対象

| データ | 確認内容 |
| --- | --- |
| `t_uketsuke_lock` → `t_uketsuke` | 残存受付ロックの一覧取得 → 対象受付の入力中フラグ等の更新 |
| `t_uketsuke_lock` | ログアウト可否のため、受付ロックの入力中フラグを確認 |
| `t_blink_shibu_setting` と支部・部門情報 | 点滅支部設定削除 → 対象支部取得 → 支部ごとの登録 |

起動・終了とも業務 DB を変更する。単なる読取テストとして扱わず、対象利用者・端末・受付番号を仕様の条件に合わせる。点滅設定の登録は画面の点滅表示を実測した証拠にはならない。
