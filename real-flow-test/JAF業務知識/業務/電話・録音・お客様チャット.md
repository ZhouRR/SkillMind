# 電話・録音・お客様チャット

## 電話発信の受渡し

Tel操作は、押下した会員情報、連絡先、依頼元、売掛先、運び先、道路管理会社等の欄に対応する名称・電話番号を電話発信画面 `JAFRSAO10002` へ渡す。連絡先1と連絡先2も区別する。

電話発信画面の初期表示には受付番号、呼出し元、発信種別等も関係する。電話番号の表示書式と発信先の値を照合し、ハイフンの有無だけで別の電話番号と判断しない。

受渡しと画面表示を確認するケースは、実際の発信・接続を確認するケースと分ける。CTIの有効性、内線、電話制御側の応答は、発信試験が指定する場合に合わせる。画面が開いたことを通話成立として報告しない。

## 録音再生の分岐

| 現在の受付番号から取得したUCIDの結果 | 動作 |
| --- | --- |
| null または0件 | 録音なしのエラー `JAFRSAEC00092` を表示する |
| 1件、Edgeプロセスなし | `JAFRSAEC00093` を表示する |
| 1件、Edgeプロセスあり | そのUCIDとログインユーザーコードで録音再生の連携を呼ぶ |
| 2件以上 | 現在の受付番号を渡して録音選択画面 `JAFRSAO02007` を表示する |

録音選択画面を期待する場合、録音レコードを2行置くだけでなく、UCID取得結果が2件以上になることを確認する。選択行の受付番号・枝番・録音日時・UCIDと、準備した録音を対応させる。重複UCIDから件数を推測しない。

現行の第2組の録音シナリオはデータセットBを使用し、受付番号54010201・枝番2、UCID001／UCID002と後続の録音時刻期待を対応させる。録音の日時は準備データの値であり、画面を開いた現在時刻ではない。

## お客様チャットの識別

JAFアプリ受付とウェブ受付は別の依頼番号で照会する。現在の受付番号と、その種別に対応する依頼番号をウェブ受付／JAFアプリチャット画面 `JAFRSAO05006` へ渡す。JAFアプリ側の依頼番号とウェブ受付依頼番号を同じ項目へ登録しない。

Webチャットで2つのメッセージを期待する場合、2件ともウェブ受付依頼番号と受付番号を揃える。片方だけJAFアプリ依頼番号に登録した準備は同じWebの対話として扱えない。

親からは対応者名・コード、依頼者名、会員番号、受付種別と参照状態も渡す。チャット画面の `IsReadOnly=true` では「対応」を非活性にする。履歴の参照と、対応開始・送信・対応終了の操作を区別する。

| 観測 | 対応させる内容 |
| --- | --- |
| メッセージの位置・順序 | 対話方向taiwaHoko=2は左側、1は右側。方向・対話日時・内容を同じレコードへ対応付け、利用者名だけで左右を決めない |
| 対応者／依頼者 | 受付担当者と救援依頼者を区別し、氏名と役割を取り違えない |
| 写真 | 左側のメッセージに関連するJAFアプリ写真連番／ウェブ受付現場写真枝番と参照先を対応付ける。対応する写真番号がnullの場合はその写真行を表示しない。null・空文字・0を同一視せず、文章の表示成功だけで写真取得済みとしない |
| 対応の開始・終了 | JAFアプリ／ウェブ受付の連携先、対象依頼番号、応答と画面状態を照合する |

## SMS

SMS送信画面 `JAFRSAO05007` には受付番号・枝番、連絡先電話番号、受付種別、到着頃時刻等を渡し、写真アップロードありの区分を使う経路がある。電話発信と同じ操作として扱わない。

画面遷移の確認、文面・宛先の確認、実際の送信結果の確認は別の範囲。未定義のSMSデータセットを補うために、実際の顧客宛先や文面を推測して使わない。
