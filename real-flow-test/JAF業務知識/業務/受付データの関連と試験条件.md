# 受付データの関連と試験条件

## 案件と関連キー

| データ・識別子 | 関連の読み方 |
| --- | --- |
| 受付番号 | 現在表示している案件のキー。子画面が受付番号で照会する場合、準備データもその番号へ関連付ける |
| 受付枝番 | 同じ受付番号の履歴・修正等を区別する番号。最新表示と指定枝番の表示を混同しない |
| 受付／受付付帯 | 共通の受付番号で対応させ、枝番を持つデータは枝番も揃える。付帯だけが別案件では必要な情報を取得できない |
| 対話履歴 | 現在の受付番号に関連する記録。チャットではさらに種別に対応する依頼番号を使用する |
| 指令／指令管理コード | 受付案件に関連する指令情報。指令管理コードと受付番号は別の識別子。指令員、基地、乗務員、号車、動態、安心コール等の表示に関係する |
| 録音／UCID | 受付番号から取得する録音識別情報。表示行数とUCID取得結果の件数を別々に確認する |
| JAFアプリ依頼番号 | JAFアプリ側の依頼に対応する番号。Web側の依頼番号へ代用しない |
| ウェブ受付依頼番号 | ウェブ受付側の依頼に対応する番号。Webチャットの全対象レコードでこの項目を揃える |
| 取引先コード | 依頼元、売掛先、運び先等の相手先を特定するコード。会社名・部門名が同じだけでは同一レコードと判断しない |
| 会員番号／聞取り会員番号 | 照会に使う聞取り値と、受付に反映した会員情報の番号を区別する |
| 車両管理番号／RS書番号／PDF格納パス | 車両情報・RS1件データ・帳票の識別情報。選択した行と開いた詳細・ファイルを対応させる |

同じ名称のデータセットA・Bでも、操作、受付番号、枝番、期待値が異なる。参照名の一致だけで準備完了とせず、期待結果まで関連がつながることを確認する。

## マスターと設定

- 車両のメーカー・通称名・分類、ナンバー地名、依頼区分・内容・追加情報、相手先の会社・部門、道路・場所等の表示名は、対応するコードとマスターデータが必要。
- 利用者・端末・所属・権限の登録は実行環境の前提。画面モードやデータセット名から利用者の権限を推測しない。
- 料金、未収・トラブルの検索年数・表示上限、連携先等の設定は対象環境の値を確認する。設定変更を試験する場合以外は、実行のために独断で値を変更しない。

## 時間に依存する表示

| 対象 | 基準と実行条件 |
| --- | --- |
| 料金案内の昼／夜 | 親画面が開く時点の端末時刻を渡し、その時刻の「時」を昼料金開始・終了の設定と比較する。受付日時だけを昼にしても条件を満たさない |
| 未収・トラブルの初期検索期間 | 受付完了日を渡した場合はその日、未指定の場合は共通処理で取得するシステム日付を基準にする |
| 予約日・時間・到着見込み | 受付・指令の状態、対象日、予約条件と連携先の応答を揃える。固定の画面期待値だけから空き状況を推測しない |
| 経過時間 | 基準日時と画面更新の時点を合わせる。固定値で比較するケースは、仕様書の判定条件が必要 |
| 会員・利用者の有効期間 | 対象の実行日と有効期間を照合する。過去日付のサンプルを常に有効なデータとして扱わない |

## 準備・実行・後処理

準備では「画面入力項目」「DB初期設定」「連携先画面項目」を区別する。画面に入力する値をDB準備済みと扱わず、連携先応答を必要とするケースを受付データだけで成立させない。

関連データを準備した後、現在の受付番号・枝番、必要な照会結果件数、表示名のマスター、時間・権限条件を確認して操作する。非同期の表示・取得が完了してから、仕様書が指定する画面・DB・ログ・通信を観測する。

更新後の同じ案件を次のケースで再利用すると、前提の入力状態、枝番、安全確認、料金案内、対話・指令の状態等が変わり得る。ケースの初期状態へ戻す必要性と方法は、対象データセットと許可された準備手順に従う。案件全体やロックを一括削除して代用しない。

未定義・名称だけのデータセット、期待結果空欄、未確定の業務判断は推測で補わない。既に暫定保留としたケースは、知識を追加しても実行対象へ戻さない。
