# 受付アプリの起動・終了

## 起動

通常起動は「統一ランチャー（LNC）を起動→登録テストアカウントでログイン→受付アプリの起動操作→受付側の初期処理」の順に行う。仕様書の「受付アプリを起動する」はこの経路を意味し、受付実行ファイルの直接起動に置き換えない。対象ケースのアカウントでログイン済みなら、そのセッションを利用して受付を起動する。ランチャー側のログイン・引数生成は共通前提として扱い、各ケースへの手順の再記載は要求しない。

ランチャーはユーザーコード・ハッシュ等の起動引数を生成して受付へ渡す。通常試験ではこの受渡しを利用し、Agent が認証値を作成・転記しない。起動引数の欠落・不正等を明示的に試験するケースは、そのケースの異常条件に従う。

以下はランチャーから通常起動された受付側の処理。

| 順序 | 動作 | テスト上の要点 |
| --- | --- | --- |
| 1 | 同名プロセスの重複を確認 | 二重起動は業務例外としてログ出力し、新たに起動した側を終了。警告画面の表示を必須とはしていない |
| 2 | 起動引数を取得・検証 | `userCd=`、`hash=`、`koikiLoginFlg=`、`trainingFlg=` を必須確認。資格情報の値は登録済み起動経路から受け取り、推測しない |
| 3 | DB 接続、受付設定、認証、ユーザー情報取得 | ユーザーコード・ハッシュの一致を認証し、有効期間・端末 IP 等からユーザーの実行条件を取得 |
| 4 | CTI 使用開始 | StationLink 使用開始を要求する。画面表示成功と電話制御の開始成功を分けて確認 |
| 5 | 前回入力の復旧、初期画面表示 | 受電・救援依頼入力、研修時はコピー画面。 |
| 6 | 起動操作ログ、点滅支部設定、コミット | 正常終了した呼出しやコミットの実測なしに、DB 更新成功を画面だけで推定しない |
| 7 | 指令・CTI のパイプ受付、地図等の初期化 | 通信開始や地図事前ロードは、それぞれの業務操作成功と同義ではない |

起動認証に一致行がなければ `JAFRSAEC00003`、ユーザー情報がなければ `JAFRSAFC00005`。引数欠落は必須チェックのメッセージになる。異常注入のケースと通常起動を混ぜず、仕様のパターンに対応させる。

## 起動時の画面表示

`JAFRSAO00010` は受付アプリの起動・終了機能。通常起動の初期処理で、次の画面を表示・初期化する。

| 画面ID | 画面名 | 起動時の動作 |
| --- | --- | --- |
| JAFRSAO01001 | 受電画面 | 初期表示する |
| JAFRSAO02001 | 救援依頼入力画面 | 通常の初期表示、または前回受付番号付きの復旧表示を行う |
| JAFRSAO13001 | 研修用依頼情報コピー画面 | 研修フラグがtrueの場合に追加表示する。救援依頼入力画面を親とする |
| JAFRSAO04001 | 受付用地図画面 | 起動処理で事前ロードする。画面表示は地図を開く操作・連携要求で行う |

受電、救援依頼入力、研修用依頼情報コピーはモードレスの独立ウィンドウ。

復旧時は救援依頼入力画面へ受付番号と `IsRecovered=true` を渡す。復旧対象がない場合は通常の初期値で表示する。

### バックグラウンド起動の表示

バックグラウンド起動では、受電画面の初期表示とCTI使用開始を省略し、救援依頼入力画面を作成・表示する経路がある。研修用依頼情報コピー画面の通常起動時の追加表示も行わない。

指令から通常起動への切替対象の業務要求を受けた場合は、受電画面の表示・CTI使用開始を行う。救援依頼入力の表示要求にはバックグラウンド状態を保持する経路がある。

## CTI の利用条件

`CtiEnabled=false` のとき、使用開始は送信を省略し、使用終了は成功側を返す。未設定・空・不正値では共通処理は有効扱いにする。無効環境で画面が開いても CTI 試験を実施済みにはしない。

開始要求には受付アプリ識別、端末番号、ユーザー ID、内線番号を渡す。応答なし・異常結果では `JAFRSAEC00010` を表示する経路があるが、開始エラーが画面起動を必ず停止するわけではない。

終了要求では異常結果・エラーコードから警告を選ぶ。`result=-4` かつ `errorCode=-6007` は `false` を返し、ログアウトを中止する。それ以外の結果もすべて同じ中止条件とは限らない。

## 終了

受電画面の終了操作は確認ダイアログ `JAFRSAQC00010` の OK 後に `Logout` を呼ぶ。

1. 本ユーザー・端末・受付サブシステムのロックに入力中フラグ非ゼロがあれば、`JAFRSAWC00001` を表示して終了を中止する。
2. CTI 使用終了が `false` なら終了を中止する。
3. 続行する正常経路では CTI プロセス終了、終了操作ログ、当該端末・アプリの点滅支部設定削除、コミットを行い、各画面とプロセスを終了する。

起動・終了の操作ログは開始／終了フラグに応じたログ出力であり、テスト結果 DB への記録ではない。
