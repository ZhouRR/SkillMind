# 依頼内容・相手先・料金案内

## 第1依頼と追加依頼

「依頼区分」「追加(依頼区分)」は依頼区分選択画面 `JAFRSAO02010` を開く。対象の依頼区分・内容・追加情報1～6と親画面の参照状態を渡す。

第1依頼は依頼区分コード1・依頼内容コード1と追加情報11～16、第2依頼は依頼区分コード2・依頼内容コード2と追加情報21～26で保持する。同じ依頼区分選択画面を使っても、対象の組を混ぜない。

第1依頼で現在と同じ区分を開く場合と参照状態の場合は、保持している内容・追加情報を渡す。入力中に異なる区分を選ぶ場合は、新しい区分を渡して内容・追加情報を未指定にする経路がある。

選択後の表示には区分略名、依頼内容、追加情報の文言が関係する。追加情報はコード値と表示文言を区別し、対応するマスターが必要。第2依頼の確定は追加依頼表示や特記事項にも関係する。

戻りデータなしの終了では選択確定として反映しない。参照状態で子画面に `IsReadOnly=true` を渡した場合、「選択」は非活性。内容が表示されても更新可能とは判断しない。

## 依頼照会

「依頼照会」は依頼情報照会画面 `JAFRSAO03002` に入電番号等の呼出し条件を渡す。選択した案件はコールバックで親画面へ反映する。モーダル性の試験期待には未確定事項がある。

## 相手先の用途

「依頼元」「売掛先」「運び先リスト」は相手先選択画面 `JAFRSAO02006` に用途別の呼出し区分、所属、支払方法、検索条件、取引先コード等を渡す。

| 用途 | 選択と保持の違い |
| --- | --- |
| 依頼元 | 呼出し区分1。依頼元用の検索条件と取引先コードを使う |
| 売掛先 | 呼出し区分2。売掛先用の検索条件・取引先コード、支払方法等が関係する |
| 運び先 | 出動場所とは別の宛先。運び先用のコード、住所、電話、座標等を扱う |
| 複数売掛 | 複数売掛画面 `JAFRSAO02004` に第2売掛先の情報・検索条件と親画面の参照状態を渡す。第1売掛先と第2売掛先の名称・部門・電話・取引先コードを分ける |

会社名・部門名・電話・担当者、住所、取引先コードは別の項目。検索条件の保持と、選択した相手先の保持も別。選択確定後の反映対象を用途ごとに確認する。

本部・支部や取引先名の期待は環境のマスターと所属情報に依存する。表示名が一致する別レコードを選んで代用しない。

## 料金案内の初期条件

料金案内は料金問合せ画面 `JAFRSAO02005` を開く。親から受付番号・枝番、RSCC、依頼区分・内容、追加情報、会員情報、道路の料金計算区分、連絡先、出動支部、牽引・運び先距離、追加工数、料金案内内容、参照状態等を渡す。

一般道、安全確認のPA／SA、その他の高専道条件では、料金計算に渡す場所区分が変わる。地図の道路名称だけで料金区分を推測しない。会員区分、場所、距離、追加工数が変われば、金額や案内内容の前提も変わる。

昼夜の初期判定に渡す作業時間は、画面を開いた時点の端末の現在時刻。受付の開始日時・完了日時とは別。現行の判定は時刻の「時」が `DaytimeChargeBegin <= 時 <= DaytimeChargeEnd` の範囲内なら昼料金、それ以外なら夜料金となる。開始・終了の時も範囲に含む。

「昼料金」を固定期待とする既存ケースは、対象環境の昼料金設定を確認し、その範囲の時間帯に開く。設定値や端末時刻を試験実行の都合で無断変更しない。

## 確定後の反映

料金問合せの確定結果には料金、案内内容、牽引距離、運び先料金の範囲、追加工数・料金等がある。親は確定結果を条件に反映する。表示金額、内部数値、案内文、DB保存はそれぞれの期待に対応させる。

依頼区分・内容や関連項目の変更は、主要情報変更や料金案内の状態に関係する。画面を開いて閉じただけで案内済みと扱わず、仕様書にある確定操作とその後の表示を確認する。

## 取消・問合せ

入力中の取消と、参照状態のクリアは処理が異なる。確認ダイアログも入力状態、枝番、予約追加、復旧案件等により変わり、確認の取消では後続処理を進めない。

問合せ・取消は、手配区分と受付履歴、指令・予約・チャット等の関係を持つ。受付番号、枝番、現在の手配区分と確認結果を前提に合わせ、単に画面表示が消えたことを処理完了の証拠にしない。
