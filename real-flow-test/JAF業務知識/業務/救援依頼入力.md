# 救援依頼入力

## 表示モード

救援依頼入力画面 `JAFRSAO02001` は、呼出しパラメータに応じて表示モードを切り替える。

| モード | 主な表示条件 | 表示後の扱い |
| --- | --- | --- |
| 新規 | 受付番号なし。電話番号なしの初期表示と、受電情報を渡した表示がある | 入力操作を試験する場合は「開始」が成功した状態を用意する。起動直後の表示だけでは入力中にならない |
| 修正 | 既存受付番号あり、自動更新・コピー・読み取り専用が false、予約修正指定なし | 受付情報を取得・表示する。編集は開始処理とロック確認が成功してから行う |
| 共有 | 既存受付番号あり、自動更新が true | 共有表示と自動更新を行う。通常の初期表示では開始ボタンは非活性。コピーとは別のモード |
| 読み取り専用 | 既存受付番号あり、自動更新・コピーが false、読み取り専用が true、予約修正指定なし | 参照用の表示。更新操作と参照用子画面の表示可否を区別する。別ウィンドウ指定の有無も保持する |

上記の既存受付番号による表示条件は電話番号が未指定の場合の分岐。電話番号と受付番号を同時に渡す経路は別の初期表示条件を持つ。試験ではモード名に加え、呼出し元と受渡し値を確認する。

復旧表示では、受付完了日時が未設定の案件のタイトルが「新規」になる場合がある。タイトルだけで新しい受付番号の採番や開始成功を判断しない。

## 名前の似たフラグ

| 項目 | 意味 |
| --- | --- |
| `FlgReadOnly` | 前画面・通信要求から渡す読み取り専用の表示指定 |
| `FgReadOnly` | 親画面の現在の入力状態。true は未入力・参照状態、false は入力中 |
| `FlgAutoUpdate` | 自動更新の表示指定。共有モードの判定に使用する |
| `FlgCopy` | コピー経路の表示指定。共有モードの代用にしない |
| `FlgAnotherWindow` | 読み取り専用を別ウィンドウで表示する指定。関連画面への受渡しにも関係する |
| 子画面の `IsReadOnly` 等 | 呼出し時点の親画面の状態等を渡した、子画面固有の参照・更新制御 |

「修正モードだから `FgReadOnly=false`」「共有モードだから入力できる」とは判断しない。表示モード、開始の成否、個々のコントロールの活性・読み取り専用属性を合わせて読む。

## 開始と受付ロック

1. 開始前は未入力・参照状態。権限と表示条件により開始ボタンの利用可否が決まる。
2. 既存案件の開始では受付可否、受付ロック、編集対象の状態を確認する。他利用者の編集中等で開始が拒否される場合がある。
3. 成功した開始処理で入力中へ移り、受付情報と端末状態等を更新する。必要な経路では経過時間の計測も開始する。
4. 開始前に表示した対話履歴・対話登録の画面は閉じられる経路がある。対話登録が登録／修正中の場合は開始を拒否するため、子画面の状態も前提に含める。

ロック確認の案内を閉じただけでは、開始成功や入力中への移行を意味しない。他利用者のロックを試験操作で勝手に削除して条件を成立させない。

## 参照・更新・終了の判定

- 読み取り専用でも、内容確認のために子画面を開ける場合がある。「開ける」「選択・登録できる」「親画面へ反映する」を別々に確認する。
- 共有の自動更新は既存受付情報の表示更新。入力中の変更を保存する操作とは区別する。試験では対象受付番号と更新前後の値を追う。
- 取消・クリアは入力状態、枝番、予約追加、復旧案件等により確認と後処理が変わる。参照状態をクリアした結果から、入力中案件の取消を実施済みとしない。
- 画面を閉じる／非表示にする操作と、受電画面からのアプリ全体の終了は別の操作。

指令から既存画面への表示要求では、`!FlgAutoUpdate && !FgReadOnly` が編集中拒否の条件になる。要求側の読み取り専用指定と、既存画面の現在の入力状態を取り違えない。

## 関連画面の受渡しと反映

1. 親画面の表示モード・入力状態・対象受付番号を合わせる。
2. 対象ボタンを押し、画面ID、表示位置、モーダル性、既存ウィンドウの再利用／作り直しを確認する。
3. 子画面の初期値と権限、参照状態、データ件数に応じたボタン状態を確認する。
4. 選択・確認・登録した結果と、キャンセル・閉じる結果を区別する。`DialogResult=true` または有効な戻りデータを条件に反映する画面がある。
5. 親画面のコード・表示名・関連項目の反映を確認する。DB保存が期待されるケースは保存後の対象データも確認する。

親画面に入力値があるだけで、子画面へすべて引き継がれるとは限らない。子画面の初期値、前回検索条件の保持、選択後の反映は、それぞれの受渡し条件で判断する。
