# 救援依頼の安全確認

## 道路と安全確認の状態

高専道、一般道は安全確認の種類を切り替える操作。「自宅」「路上」「PK」「その他」は一般道側の停止場所を区別する。道路・住所等の出動場所情報と、安全確認の選択状態は関連するが、同じ項目ではない。

| 前提と操作 | 判定する状態 |
| --- | --- |
| 一般道で確認した内容を保持し、再び一般道の安全確認を開く | 一般道が選択され、対象の停止場所と安全確認項目が再表示される。保持試験では最後の押下も一般道とする |
| 一般道から高専道へ切り替える | 高専道側へ切り替わり、一般道の自宅・路上・PK・その他、追突の危険なし等の選択をクリアする。停止位置、ハザード、左端停車、避難・同乗者等も切替処理のクリア対象になる |
| 高専道から一般道へ切り替える | 一般道側へ切り替え、高専道側の状態と切替に伴う関連項目を確認する。切替前の選択を無条件に保持する期待にしない |
| 親画面の安全確認を開く | 現在の受付情報を基に対象の道路・停止場所・安全確認項目を表示する。別案件の状態を引き継いだものと扱わない |

同じ道路での再表示と、道路を切り替えた後の初期状態を区別する。座標が既に存在する場合、道路区分の更新条件も変わるため、安全確認の切替だけで地図上の道路情報が常に初期化されるとは判断しない。

## 子画面の表示と反映

救援依頼入力画面の「高専道(安全確認)」「一般道(安全確認)」「安全確認」は、救援依頼入力(安全確認)画面 `JAFRSAO02002` を開く。受付番号とアラート処理の条件を渡す。

親画面は受付番号を渡す前に、道路・安全確認の変更を受付データへ反映する経路を持つ。子画面はその受付情報を取得する。親画面のチェック表示だけを操作して、子画面が同じ値を読むと推測しない。

子画面では道路・停止場所・受付状態により、表示する安全確認項目と操作可能な項目が変わる。高専道と一般道で同一のチェック項目一覧を前提にしない。

確認完了後は、再表示した子画面のチェック状態と、親画面の安全確認表示を対象項目ごとに照合する。保持を確認する場合は「選択→確認完了→同じ道路で再表示」の順序を保つ。

## アラートとの区別

安全確認とアラート通知は別の観測。子画面から返る表示条件コード・手順コード、親画面の状態、指令との通知条件によってアラートの扱いが変わる。

安全確認画面を開けたことだけで指令への通知成功としない。アラートが期待されるケースは、対象受付番号、指令側の応答、親画面のインジケータ等を仕様書の範囲で確認する。通知条件を成立させるために試験範囲外の指令を追加しない。
