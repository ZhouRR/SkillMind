# 対話履歴・帳票・研修

## 対話履歴

対話画面は対話履歴画面 `JAFRSAO05001`。現在の受付番号で受付・対話・指令等の情報を取得する。既に開いている対話履歴を閉じて表示し直す経路がある。

| 表示項目 | 意味 |
| --- | --- |
| 対話相手 | 相手先種別等に対応する業務上の相手。相手先種別1は「救援依頼者」 |
| 対応者 | 対話に対応した担当者の氏名。救援依頼者という種別表示とは別 |
| 受信日時・対話手段・分類・内容 | 同じ対話レコードの項目を対応付ける。受付日時や録音日時と混同しない |
| 指令・基地・乗務員・号車・動態 | 現在の受付に関連する指令・マスターの情報 |
| 経過時間 | 作業完了日時が未設定、かつ車載ボタン状態変更日時が設定済みなら、表示時の端末時刻との差を分単位の整数で表示する。それ以外は空文字。期待空欄を自動で0や現在値に補わない |

相手先種別1・対応者名「受付花子」の準備では、対話相手は「救援依頼者」、対応者は「受付花子」。担当者名を対話相手の列へ置かない。

経過時間の基準は対話の受信日時や受付開始日時ではなく、上記の指令側の日時。判定条件が未記載の保留行は、この計算条件を収録しても実行対象へ戻さない。

指令取消・TS対応結果登録等には個別の権限と画面状態が関係する。別ウィンドウ参照の呼出しでは `ON` の読み取り専用指定を渡す経路があり、登録・修正等を非活性にする。親のモード名から、全呼出しの同じボタン状態を推定しない。

## 特記事項

特記事項選択画面 `JAFRSAO02015` の候補選択と、親画面の特記事項欄への反映を区別して確認する。既存の特記事項、追加依頼や状態変更により付加する文言がある場合は、全体の文字列と改行を対象仕様の期待に合わせる。

文字列の表示、編集確定、受付データの更新は別の観測。候補が表示されたことだけで保存済みとしない。

## RS書・RS1件データ

RS1件データリストは選択行の情報で遷移先が変わる。PDF格納パスが空の場合は管理番号を渡してDTC詳細情報画面 `JAFRSAO02016` を開く。パスがある場合はPDFを開く。

管理番号、RS書番号、PDF格納パス、車両・DTC情報を同じ対象行へ対応付ける。PDF表示とDTC詳細表示を同じ期待にしない。ファイルの存在・読取可否・外部表示環境が必要なケースは、その条件を確認する。

RS書表示の操作と、RS1件データリストの行選択は別の操作。各ケースで指定された対象帳票・レコードを確認し、別案件のPDFが開いたことを成功としない。

## 研修データ保存呼出

研修ボタンは研修救援依頼データ保存呼出画面 `JAFRSAO13003` を開き、受付番号・枝番を渡す。研修画面の表示権限と保存の登録権限は別。

保存にはデータ名、説明、元の受付番号・枝番等を使用する。説明は入力した文字列を保存する。現行の「説明テスト」を入力するケースでは、呼出し後も「説明テスト」を期待し、「テスト」を除いた文字列にしない。

保存操作、保存データの識別、再度呼び出したデータの表示を分けて確認する。元案件の表示と保存済み研修データの表示を同一視しない。保存対象は試験用の案件・保存データの範囲に限定し、既存の研修データを一括削除して準備しない。
