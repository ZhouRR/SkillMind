架构原则 逻辑架构 AI 执行时序 部署结构

模块化单体 + 引擎抽象

API 与 Worker 共享同一代码库,业务层只依赖 AgentEngine 抽象;Claude Agent SDK 是默认实现,而不是领域模型,可替换、可升级。

不可变快照 + 追加审计

Run 冻结目标与权限上限;用户交互追加 Segment,技术重试追加 Attempt,多个顺序 Session 共享同一审计主线。PostgreSQL 是唯一权威记录。

受控自主 + 硬权限边界

Agent 可在 ExecutionProfile 内自主规划;工具按 capability、参数与资源范围逐次校验,工作区能力分层开放,凭据不进入 Agent 环境。

复用既有入口的最小部署

不自带网关、不发布宿主机端口,以最小动态路由接入部署环境既有的 Traefik;内部服务全部隔离在私有网络。

逻辑架构(C4 容器视角)

表达组件归属、主要依赖与安全边界,不展开单次任务的调用时序。虚线卡片为路线图中的规划项。

AI 任务执行时序

能力提交、可靠入队、Agent 自主 Loop、用户交互、多 Session 延续、Tool/Effect 校验与结果持久化。Run 可在 RUNNING 与 WAITING_FOR_INPUT / WAITING_FOR_APPROVAL 间追加 Segment,最终进入终态。

  1. 01 任务提交QUEUED
    Web / 工作空间 提交目标、资源绑定、参数与幂等键 FastAPI

    会话 + CSRF 校验通过后,检查必要 ResourceBinding 与可选参数契约;成员越权与资源不存在返回同一错误形态。

  2. 02 快照冻结QUEUED
    FastAPI 写入 Run 快照 + 事务 Outbox PostgreSQL / 存储

    保存目标、精确 Skill/Blueprint、权限、资源选择与限制，创建 Segment 1；状态与待投递 Outbox 同事务写入。内容冻结时点按资源种类区分。

  3. 03 可靠分发QUEUED
    FastAPI Outbox 投递执行消息 队列(Redis)

    队列只承担分发;即使消息丢失,数据库中的权威状态也能驱动重新投递。

  4. 04 领取执行PREPARING
    Worker / 编排器 领取当前 Segment，创建带租约的 RunAttempt 与工作目录 PostgreSQL / 存储

    租约防止双 Worker 并发接管;用户交互追加 Segment,基础设施重试才在当前 Segment 追加 Attempt。

  5. 05 启动 AgentRUNNING
    Worker / 编排器 execute(context) → SDK 会话启动 AgentEngine · SDK

    Worker 准备资源并冻结本 Segment 的 AgentTaskBrief，再构造 RunContext。业务层只依赖 AgentEngine；Agent 收到完整 guidance 与权限边界，活动超时由 Worker 强制。

AGENT LOOP · 在 required rules 与权限内自主规划
  1. 06 过程可见RUNNING
    AgentEngine · SDK 流式输出、步骤与用量事件 Web / 工作空间

    持久事件可按 sequence 重放并由前端去重；TEXT_DELTA 消耗序号但不持久化，缺号正常。断线重连不能保证恢复每一段流式文字。

  2. 07 工具请求RUNNING
    AgentEngine · SDK MCP 工具调用请求 Tool Gateway

    每次调用都携带 ResourceBinding 与执行上下文;网关据 Run 快照逐次裁决,不存在「模型建议即授权」。

observe/workspace/propose · 参数在范围内 按 ExecutionProfile 自动放行 → 参数级硬校验 → Provider/隔离 workspace 执行 → 返回标准化数据、Artifact、Evidence 或 ChangeProposal,同步写入审计。
apply 或未登记/越界请求 注册 apply 默认创建精确版本/checksum 审批并暂停;命中 LOW exact 预授权才免询问。Redmine 还必须通过 CAS/idempotency discovery,未登记、越界、任意 host Shell 直接 DENY。
  1. 08 交互暂停WAITING_*
    AgentEngine · SDK 结构化澄清 / Review / Effect approval Web / 工作空间

    Worker 持久化 Interaction 与 checkpoint 后释放 lease。用户响应经授权与版本校验创建下一 Segment;普通超时不采纳默认回答,审批超时使 Proposal stale,再 resume、fork 或 replace Session。

  2. 09 结果校验RUNNING
    AgentEngine · SDK Outcome + Artifact/Evidence/Proposal + session_id Worker / 编排器

    平台校验通用 Outcome 与引用所有权，声明了 output schema 时追加结构校验；业务规则和结论语义是否正确需单独验收。

  3. 10 终态落库SUCCEEDED
    Worker / 编排器 保存 Result / Evidence / Effect verification / 会话全文 PostgreSQL / 存储

    终态快照事件是该 Run 的最后一条事件,SSE 以它作为推送结束的判定;失败路径同样以终态事件收敛。

  4. 11 结果交付SUCCEEDED
    Web / 工作空间 展示报告、证据定位与评价入口 Web / 工作空间

    用户看到结论、报告、证据出处、Segment/Session lineage 与外部效果验证，并可追加评价。新目标重新创建 Run；当前没有 child Run 创建接口。

交互继续与故障恢复使用不同审计对象 用户答复、Review 或批准在同一非终态 Run 追加 RunSegment，可顺序 resume/fork/replace Session；Worker 故障只在当前 Segment 追加 RunAttempt。终态 Run 不重新打开，新目标创建新的 Run。

部署结构(Linux + Docker Compose,复用既有入口)

部署环境已有共享 Traefik 时,ProjectMind 不部署自己的网关、不发布任何宿主机端口。部署契约以 docs/01 §2.6 与 compose.yaml 为准。

既有共享入口(ProjectMind Compose 外部)

existing-traefik

统一监听 80/443 与 TLS 终止;证书、Dashboard、入口策略均由环境运维统一管理

域名 + 上下文路径

/projectmind/api/*(含 SSE)路由到 api;/projectmind/* 路由到 web

external edge network

由运维预创建并接入既有 Traefik;ProjectMind 仅声明最小动态路由

HTTPS · REST + SSE · 会话认证

ProjectMind Compose:external edge + internal backend(共 7 服务)

web

React 静态资源与工作空间;仅加入 edge 网络,不发布宿主机端口

api

FastAPI:认证、任务、执行与 SSE;加入 edge + backend,不发布宿主机端口

internal backend network
worker

Segment 编排 + Claude Agent SDK,活动会话使用独立 claude 子进程;等待用户时释放租约与进程

migrate

一次性数据库迁移任务(alembic upgrade head),完成后退出;仅加入 backend

worker tick

定时与周期触发已内置于 worker，不额外部署 scheduler；不承诺停机补跑或全局精确一次

sandbox

脚本隔离执行;script.execute 开放时作为独立隔离任务加入

队列 / 持久化 / 制品
postgres

PostgreSQL 17:业务、审计、证据与会话的权威记录

redis

Redis 8:任务队列与短期唤醒;不承担最终数据

object-storage

MinIO:Skill 包、文档与报告产物;不对外暴露控制台

deployment-secret

凭据由部署环境或 /run/secrets 提供;ProjectMind 仅解析版本化 locator,不新增公开服务
