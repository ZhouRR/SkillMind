# 使用指南

Skillmind 将 Skill 原文作为执行依据，把输入选择、资源访问、任务运行、外部变更和结果审计集中到项目中。当前可用范围与尚待验证部分见 [Roadmap](../planning/roadmap.md#当前执行状态)。

## 从 Skill 到结果

1. 在组织技能库导入 Skill，核对解析得到的任务、必要输入和资源声明，再发布版本。
2. 在项目中启用该精确版本，通过「资源与连接」配置凭据与访问权限。
3. 选择任务和文档范围，核对预检内容后启动；需要重复运行时，在任务卡片设置定期执行。
4. 在工作空间查看进行中任务和待处理事项；缺少业务信息时回答问题，需要批准时处理具体变更。
5. 在「完成与报告」选择任务查看最新一次终态执行的总结；进入执行详情查看完整结果、附件、证据和评价。

发布、项目启用与资源就绪分别检查。平台不会把模型推测当作实际输入或自动扩展文档范围。新导入的 Skill 采用最小输入/资源声明加冻结原文执行，无需事先拆解为固定业务流程。

## 页面怎么用

| 页面 | 主要用途 |
| --- | --- |
| 概览 | 待办、最近执行及项目入口 |
| 组织技能库 | 导入、解释、发布、项目启用和版本清理 |
| 任务 | 按名称、标识和定期执行状态检索，启动或设置调度 |
| 工作空间 | 待处理、执行中与按任务汇总的最新报告 |
| 执行历史 | 筛选、耗时、单次详情及回收站管理 |
| 项目文档 | 上传、目录选择、改名、移动、预览、下载与回收站 |
| 资源与连接 | 凭据、授权范围，以及 PostgreSQL、文档库、Git、MCP 等连接 |
| 项目与账户 | 成员、归档、账户安全及管理员管理 |

ADMIN 管理组织技能、项目和资源；普通用户在获授权项目中操作。API Key 可供其他应用调用，当前没有逐资源的细粒度 Key 权限，参见 [API 指南](../development/api-usage.md)。

## 自动批准与结果阅读

任务启动时的自动批准是对本次运行的明确同意。当前页面的自动批准选项同时提交数据库、文档、Git 和 MCP 的同意，服务端按各项原始同意范围核验。权限检查、冲突检查和回读仍然执行；取消自动批准后逐次批准。

平台执行成功、结果是否完整与业务 PASS/FAIL 是不同事实。报告模板展示模型提供的结论及引用，不自行推断测试通过；原 Skill 明确要求的报告仍作为业务成果保存。

## 整理旧数据

执行历史和文档支持移入回收站、恢复及完全删除。先核对预览中的关联成果和阻断引用；执行清理保留原始输入及共享引用，不自动删除外部业务数据库或 Git 记录。
回收站内记录仍可能引用 Skill 版本；确需删除版本时先处理这些引用。完全删除不可恢复，保留必要审计。

系统组成见[架构与术语](architecture.md)，错误处理见 [Runbook](../operations/runbook.md)。
