业务能力地图

把项目管理经验变成可复用、可审计的 AI 执行力

ProjectMind 是 Skill 驱动的项目管理 AI 执行平台：把团队沉淀的分析方法导入为平台资产, 在项目边界内把目标、资源与指导完整交给 AI Agent 自主执行,每一步都留下证据与审计记录,并通过用户交互与人工评价持续改进。 本页说明平台由哪些业务能力组成、Skill 与任务如何流转；字段与状态机见 领域模型，实现与验收差距见 实施计划。

经验资产化

把 Codex、Claude Code 等生态的通用 Skill 与团队自有方法论,统一转换为可审核、可版本化的平台资产,一次沉淀、多项目复用。

全程可审计

执行保存精确版本、输入与权限；持久事件、工具调用、证据与结果可追溯。流式文字增量不全部持久化；资源授权与内容快照是不同边界，文档冻结链路仍在联调。

默认安全边界

AI 只能使用项目授权的资源与登记工具,凭据不进入 Agent 环境;只读能力自动执行,业务选择与外部效果按策略暂停确认。

人机协同改进

AI 原始结论永不被覆盖,人工评价与修订以追加方式记录,形成 Skill 持续改进的数据闭环。

业务能力全景

由上至下阅读职责层级;同一行是一组共同完成该层业务目标的对象。结构关系,非执行顺序。

已有实现，验收见计划 规划中
01

组织与治理

决定谁能进入平台、管理资产,以及在项目中执行什么操作。

ADMIN

平台管理员

管理用户、项目与平台配置,负责 Skill 的审核与发布。

USER

项目成员

通过项目成员关系获得任务执行、结果查看和评价权限。

Project

项目隔离边界

成员、数据、任务、执行与结果都从属于明确项目,互不可见。

Session / CSRF

企业级会话安全

浏览器会话认证与跨站防护,资源不存在与越权同样不可探测。

02

Skill 资产

把通用 Skill 转换为经过审核、可发布、可回溯的平台资产。

SkillSource

原始 Skill 包

完整保留导入来源与原始文件,后续解释与发布都可回溯到源头。

Skill Interpreter

智能解释器

AI 理解 Skill 能做什么、需要哪些资源、目标与规则、交付物和效果意图,并保留来源依据。

Draft / Preview

草稿与人工调整

解释结果先进入预览,支持追加式修订与差分对比,不直接进入项目。

SkillVersion

发布版本

通过发布门禁后形成不可变版本;项目执行永远锁定到精确版本。

03

项目应用

把已发布 Skill 与项目数据、知识组合为可操作的工作空间。

ProjectDocument

项目文档库

上传与管理项目文档,经安全校验后作为任务的受控数据源。

Integration

外部数据源

以 SecretReference、版本化能力与精确 scope 绑定 Redmine、SVN、Git；写入默认先展示 Proposal。

SkillComposition

项目模块

把多个已发布 Skill 组合为业务模块,工作空间按模块组织任务入口。

ExecutableTask

可执行任务目录

从已发布能力蓝图投影任务目录:目标、资源前提、指导、交付物、就绪度与效果策略。

04

AI 执行

以不可变权限边界持续完成目标,记录用户交互、业务分段、技术尝试与多个 Agent 会话。

Run

持续执行线程

冻结目标、Skill、权限上限、资源与限制,可通过多轮交互持续到明确终态。

RunSegment / Attempt

业务分段与技术尝试

用户答复或批准追加 Segment;Worker 重试与故障恢复追加 Attempt,两类历史均不覆盖。

AgentSession

Agent 会话

保存 AI 会话与恢复上下文,同一 Run 可顺序 resume、fork 或切换新会话继续。

05

结果与改进

把 AI 输出转化为可追溯证据、可阅读报告与可持续评价数据。

Evidence

分析证据

保存票据、代码、文件位置与工具调用来源；结论是否被证据充分支持仍需模型质量与人工验收。

Outcome / Proposal

结果、报告与变更提案

保留 AI 原始结果与报告;外部变更独立审查、执行和验证,终态后不被覆盖。

Evaluation

人工评价与修订

以追加记录评价准确度、意见与修订,形成 Skill 改进依据。

Skill 资产生命周期

从通用 Skill 进入平台,到成为项目可使用的受控资产。

  1. 导入保留原始资产
  2. 解释生成能力蓝图
  3. 调整人工修订与预览
  4. 发布门禁校验并版本化
  5. 启用Project 显式启用精确版本

任务执行闭环

从任务配置,到结果被人工评价并沉淀为改进数据。

  1. 配置目标与资源绑定
  2. 执行Agent 自主分析
  3. 交互澄清、Review、批准
  4. 结果证据、报告与效果
  5. 评价人工反馈修订

一次完整任务的业务时序

阶段一 · 任务准备
  1. 01 任务准备未创建 Run
    用户 选择能力并补充目标 工作空间

    从任务目录选择「票据品质分析」,确认分析目标、期望交付物与本次需要关注的观点。

  2. 02 执行前确认用户明确触发
    工作空间 展示资源、指导、自主等级与效果策略 用户

    平台逐项展示 Ticket、代码、文档等资源要求与候选绑定;用户可覆盖选择,并确认 SUPERVISED 等执行等级。

阶段二 · 受控执行
  1. 03 创建执行已入队
    工作空间 提交目标、资源绑定与幂等键 API / 任务中心

    API 校验成员权限与必要资源，冻结 Skill、目标、权限、资源选择和限制。资源选择不自动等于外部内容已取得。

  2. 04 持久化权威记录
    API / 任务中心 写入执行记录与初始事件 数据库 / 存储

    Run、Segment 1 与待投递 Outbox 在同一事务保存；数据库是正本，异步消费者按幂等规则处理重发。

  3. 05 领取任务准备执行
    API / 任务中心 Worker 领取任务并取得执行租约 Agent 运行时

    领取已有 Segment，创建技术 Attempt 与工作目录；准备资源并冻结本段 AgentTaskBrief，装载完整 Skill guidance 和授权边界。

  4. 06 Agent 执行运行中
    Agent 运行时 自主规划并请求登记工具 工具 / 数据源

    Agent 可重排推荐步骤并追加只读验证;工具网关逐次校验能力、参数与项目绑定,不会因模型更强而放宽权限。

  5. 07 分析取证运行中
    工具 / 数据源 返回标准化数据与证据定位 Agent 运行时

    AI 组合票据、代码与 Skill 规则进行分析，记录工具调用、用量与证据。证据不足时应明确保留未知；平台结构校验不能保证模型不产生错误结论。

  6. 08 人机交互按需等待
    Agent 运行时 请求澄清、观点 Review 或效果批准 工作空间

    平台保存 checkpoint 并释放 Worker;用户响应后追加新 RunSegment,按上下文 resume、fork 或启动新 AgentSession 继续。

阶段三 · 交付与改进
  1. 09 结果落库执行成功
    Agent 运行时 提交 Outcome、证据、产物与可选变更提案 数据库 / 存储

    平台校验结果结构与引用归属；Skill 业务规则的语义正确性另行验收。外部变更先形成 Proposal，经批准或精确预授权执行后回读验证。

  2. 10 结果交付实时推送
    API / 任务中心 推送完成事件、报告与证据 工作空间

    页面支持断线续传与事件去重,最终展示结论、报告、证据、各 Session 历史和外部效果验证。

  3. 11 人工闭环追加评价
    用户 评价准确度、添加意见或修订 API / 任务中心

    评价作为新记录追加,AI 原始结果不被覆盖;评价数据进入后续 Skill 改进分析。

越界或写操作怎么办? 未登记工具、扩大数据范围与任意宿主 Shell 会被硬拒绝;注册的外部效果先生成 Proposal,默认等待批准,只有明确预授权范围可直接执行。
执行中途故障怎么办? 执行记录保持不变;故障只在当前 Segment 追加新的 Attempt,恢复工作目录与 AI 会话后继续,不会伪造新的用户决定。

平台承诺的三条业务边界

这些约束需要实现、负向测试和部署验收共同证明。授权、内容与物化副本的冻结时点，以及文档联调差距，见资源快照设计。

项目即隔离边界 数据源、文档、任务、执行与结果都从属于明确项目;跨项目不可见,越权访问与资源不存在同样不可探测。
定义与执行分离 任务定义可以持续调整;Run 冻结目标与权限上限,用户交互追加 Segment、技术恢复追加 Attempt,审计口径始终一致。
AI 原始结果不可篡改 AI 结论保持不可变,人工判断通过评价与修订记录持续追加——既保护审计,也沉淀改进数据。
