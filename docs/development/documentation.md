# 文档维护约定

## 正本与派生内容

| 内容 | 放置位置 | 更新方式 |
| --- | --- | --- |
| 产品、术语、整体结构 | overview/ | 解释目的与组件关系，链接详细规则 |
| 不变量、协议语义、失败恢复 | design/ | 每个主题一个正本；标明现状与目标 |
| 当前状态、顺序和验收缺口 | planning/roadmap.md §13 | 实现/部署/专项验收分别举证 |
| 开发命令和变更指南 | development/ | 写明工作目录、依赖、输入和副作用 |
| 配备、backup、restore、故障处理 | operations/ | 根据操作风险给出前置和成功条件 |
| 业务质量标准 | acceptance/ | 说明样本、指标、数据隔离和人工判定 |
| 当时的实施记录 | history/ | 保留历史事实；新结论追加，不倒改旧报告 |
| 代码入口与 agent 约束 | PJM/*/README.md、AGENTS.md | README 做导航，AGENTS 约束变更 |
| Skill 输入与解释器指令 | PJM/skills/** | 可执行资产，遵守 version/hash/fixture 同步 |
| 浏览版 | docs/index.html | 从 Markdown 生成，不手改正文副本 |

Markdown 是可维护来源。浏览版只嵌入 docs Markdown、workspace/代码 README 和 AGENTS，不扫描 .env、内部配置、业务 Skill 原文、凭据、测试 Gold 或任意源码。[契约联调指南](contract-workflow.md)是开发流程文档，不承担领域字段定义或当前失败登记；两者仍分别放在 design/ 和 planning/。

## 写一份设计

先在[设计责任索引](../design/README.md)确定主题归属。开头写用途、状态和前置文档；正文依次说明场景、数据/职责、成功与失败流程、兼容性、实施入口和验收。表格用于比较，短流程图用于表达分支，代码示例应能通过现有契约。

推荐使用以下骨架，可合并不适用的章节，不为了套模板制造空文档：

```text
标题：说明本页负责的一个主题
定位：设计/实现说明/操作指南；状态来源与前置阅读
1. 场景与非目标：为什么要做，明确不做什么
2. 决策与理由：规则、替代方案、取舍及受影响边界
3. 数据与职责：正本、调用方、冻结时点、现有 Schema/代码入口
4. 运行与失败：成功、拒绝、重试、幂等、并发、恢复
5. 兼容与实施：历史数据如何读取，哪些消费者需要同步
6. 验收：给定条件、操作、可观察结果、未覆盖范围
```

### 状态与证据

- 区分“设计要求、工作副本、已验证行为”。实现提供代码入口；待实现明确缺少的 API/Schema/页面，不写成操作步骤。已有新代码但缺回归时如实写明，不称为“完全未实现”或“已交付”。
- 冲突写清现状、影响、目标和同步范围；不弱化设计，也不在文档整理中擅自修补应用实现来取得绿色结果。已有测试失败同样保留原因。
- 证据写核对时点和范围。文档 build 不刷新应用回归日期；控制流推导不是故障注入，mock SQL 不是实 DB 并发，配备不是全部专项验收。
- 每条“已验证”说明哪些层是真实实现、哪些是替身。例如 ASGI + Redis 可能仍未启动 HTTP server，成功登录测试也可能只用 fake 保存 Session；共享文案的三语测试不等于真实页面交互。测试名包含 real 或集成不能代替这项说明。
- 状态只在 planning 维护，详细验证追加 history，设计只保留影响和证据链接。新结论不倒改旧报告；历史归档不作为当前功能的保证。
- field、enum、required 从对应 Schema/route 核对，示意结构注明目标或语义摘要。Schema、OpenAPI 或消费者不一致时先登记[交付断点](contract-workflow.md#遇到未接齐的交付链)，不选择较新的一份替所有层作保证；代码文件、DTO 或测试存在不等于整条链路可用。

### 目录、语言与阅读

- README/AGENTS 使用日文，设计正文沿用中文，协议与代码标识保持原样。每页一个 H1、正文从 H2 开始；新独立设计使用本页层级，不沿用旧 PLAN 的 26.x。
- 标题描述稳定主题，状态写在正文。保留旧章作短入口；确需改锚点时同步现行引用，历史事实不倒改。使用相对链接，旧编号由[文档索引](../README.md#旧番号の対応)解释。
- 总索引按目的提供少量第一跳，design/README 分配设计责任，代码 README 指向实现和测试。细节留在正本，排障留在 Runbook，不在每层复制大表。
- 独立设计先划责任：创建负责请求身份、资源负责内容、Runtime 负责已有 Run、调度负责触发。抽出主题后同步相邻入口与浏览版顺序，不复制完整失败/恢复表。
- 长 README 按读者动作分节，历史索引按主题组织。复杂规则先给具体例子，区分计划、事实和未知；图示不虚构数据库所有权或已实现步骤。需要同时理解的证据与限制放在同一单元格，不让手机读者横向滚动后才能发现保证的前提。
- 工作登记需要同时包含长篇范围、状态和验收时，改用稳定 ID 的独立小节与短跳转索引，不把整段设计塞进宽表。保留原 ID/范围和旧父章节锚点；概览仍可使用简短比较表。
- 概览只保留“有什么基础、还要做什么”的短摘要并链接责任项。正式代码 README 提供页内动作入口，详细接线留在原章节；优先减少第一屏和手机上的查找成本，不为整理再造一套进度表。
- 运行验收与质量评分服务不同读者：前者说明准备/执行/失败，后者说明样本/隔离/分母/人工判断。拆分时保留旧编号入口，将具体规则移到唯一正本；如 [JAF 运行验收](../acceptance/jaf-quality.md)与[Benchmark](../acceptance/jaf-benchmark.md)。评价答案仍在仓库文档和执行资产之外，不能以“补齐文档”为由导入真实 Gold。
- 操作手册按决策拆分：首次启动、版本发布、数据恢复、症状排障分别负责一条路径。检查、启动、写入验收与破坏性替换须显式区别；旧步骤移为尾部兼容入口，不留下两份可独立复制执行的命令块。功能开关的名称不能代替所有 job/cron/实例的停写证明。
- 同主题有交付到不同层的工作副本时，先画实际调用与断点，再写目标行为与验收。例如[用户生命周期](../design/user-lifecycle.md)独立于会话协议：API、Schema、快照、Web 和部署分别说明，不能把尚未交付的链路写成可直接执行的操作手册。UUID、row_version 或审计表的存在也不自动证明可信来源、完整并发控制和追加式保护。
- 同为人工操作也要按结果分工：[普通答复](../design/user-interactions.md)、外部批准和结果评价各有身份、事务与恢复协议。先用例子说明事实，再给代码入口；不能把一个页面已实现的重发机制推广到所有 mutation，也不能从非成功 HTTP 状态推断没有提交。
- 结果说明先区分执行终态、模型交付、引用与人工判断。[结果正本](../design/results-evaluation.md)写清实际校验位置、修订原值根和未知提交；契约字段存在、引用计数或建议保存不能被描述为内容已验证、原值已更新或业务质量已通过。
- 生命周期说明先区分用户意图与实际操作。[项目正本](../design/project-lifecycle.md)区分成员移除、账户停用、归档、取消、删除与字节清理；沿全部引用和消费者核对，不能把“无 Run”、行锁、单行状态或 204 写成完整的删除/审计/并发保证。
- 跨存储资产按保存边界说明：[文档资产](../design/document-lifecycle.md)负责上传、目录、下载、引用保护与清理，[资源快照](../design/resource-snapshots.md)负责 Run 范围和副本。配额检查、MIME 申报、禁脚本预览、数据库 commit 与 204 各有不同保证，不因共用 storage 接口而合并。

### 设计评审的核对点

沿实际调用方与消费者核对，不因共用一个 helper 就宣称所有事务、输出契约和生命周期相同。

| 主题 | 必须说清的边界 |
| --- | --- |
| 身份与凭据 | 登录入口配额、challenge、会话/CSRF 与外部 Secret 分开；核对正文校验前后的计数、分阶段 Redis 操作、TTL/退避、锁后时效、多页面、提权/撤销入口和密钥层级。角色权限表不证明管理 API 已存在，原子脚本不证明所有维度与 DB 一起提交 |
| 执行与停止 | deadline 控制哪段 await、谁清理、何时提交；取消意图、业务终态和进程停止分别举证。终态与等待事务分开检查，不用正常流程承诺所有故障已收束 |
| 状态与版本 | 状态属于哪个对象；compatibility、gate、发布、Project 启用、运行就绪不合并。内容不可变不等于生命周期 metadata 不可变；回滚先确认可执行的逆向路径 |
| 外部写入 | 请求/批准身份、远端执行、回读和平台保存分开；内容一致不证明原执行，可重试不证明分阶段恢复。未实现的回执不先变成公开字段 |
| 并发与查询 | 核对数据库条件写入/锁，不只看 request 版本号或 409。确认实际过滤范围和分页；摘要不是账本，同名 task 不是互斥域 |
| 预算与子结果 | 用量的来源、单位、累计/增量和保存方式先于余额公式。追踪 prompt、冻结依据、Schema、validator、Gateway 和消费者；共用 validator 不等于共用输出契约，失败也不只来自 Python 异常 |
| 生成界面 | 同名 module API、内部模型、声明式视图与 iframe 预览分开。核对实际调用、完整构建身份、产物/CSP/报告证明、旧实例消息与独立展示回退；常量或字面检查通过不是执行许可 |
| 运维与恢复 | 标明只读、写入验收或破坏性恢复；命令交代环境、前置、失败停止及成功条件。注明敏感输出、缺少的 CLI 和不可被本地恢复撤销的外部效果 |

## 一次整理的更新顺序

1. 核对代码和契约，先向协作者说明冲突、影响面与本次是否修改实现。
2. 修改负责该规则的设计，再更新引用它的概览、操作指南与代码 README；不复制整段规则到所有入口。
3. 实现进度只更新 roadmap §13，旧章节与代码注释所用编号通过引用索引兼容。历史记录追加新结论，不覆盖旧时点。
4. 对照全部正式 Markdown 清单确认覆盖。Skill 的 SKILL.md/references 是执行资产，不因属于 Markdown 就移动或改写；变更时另走 version/hash/fixture 流程。
5. build、check、文档工具回归与相关契约检查后，再做浏览器人工可读性检查并记录实际范围。

代码目录新增 README 时同步工程入口。[script README](../../PJM/scripts/README.md)说明各工具的副作用；新加深层文档时明确更新 build 的 `source_paths()`，不要改成递归扫描所有源码、Skill 和配置。

历史正文较长时先维护[目的索引](../history/README.md)，保留既有章节锚点。索引只回答“到哪里找证据”，不复制进度表、测试件数或把历史操作冒充当前指南。

计划页只保留当前状态、接续工作和有日期的证据入口。已经完整记录在 history 的旧失败表与长篇实施摘要，不在计划中再维护一份；压缩时保留旧标题/锚点，并确认原事实仍能从链接找到。领域内跨资源共用的协议放在独立同级章节，不把 Run 级准备与恢复埋在某一种文档选择下面。

## 生成和验证浏览版

以下在 `PJM/` 执行。依赖只用于文档工具，不改变 Backend/Web 运行依赖，也不需要虚拟环境。

```bash
python3 -m pip install --user -r scripts/docs-requirements.txt
python3 scripts/build_docs.py
python3 scripts/build_docs.py --check
python3 -m unittest discover -s scripts/tests -v
```

若 user site 不可写，可把依赖安装到工作区外明确的临时目录，并用 PYTHONPATH 指向它；不因此修改应用依赖或创建 venv。

build 检查 Markdown 标题层级、代码块、本地链接与章节锚点，并验证文档中带 `view_version` 的 ViewSpec JSON 示例。历史归档保留原有层级，不为新样式倒改旧正文。生成的 index.html 包含所有可浏览正文，可直接离线双击打开；不使用 CDN、运行时 fetch 或服务端。

检查 Python 文档工具的风格时使用 Backend 开发依赖，并显式传 `--config backend/pyproject.toml` 给 Ruff 的 check/format；从 `PJM/` 运行时不会自动发现这个子目录配置。使用 `--no-cache`，不为文档检查在仓库生成缓存。

搜索支持标题、正文、代码示例和文档 path。结果按文档分组，文件名精确匹配及标题/path 匹配优先于正文引用；显示分类/path、命中章节和高亮片段。点击可直接进入章节，每篇先显示最多三个命中章节，更多位置可用浏览器查找。搜索章节包括未列入简短目录的 H4 以下标题，并复用同一套锚点。历史默认不参与搜索，需要明确勾选；普通导航中历史单独折叠。

`docs/` 下新增 Markdown 会自动进入浏览版；推荐阅读顺序维护在 `build_docs.py` 的 `FIRST_PAGES`。首次打开、点击品牌和未知文档的返回链接统一进入 docs/README 的目的导航；产品与架构紧随其后，已有深链接仍直接打开原章节。开发指南按“环境 → 变更入口 → 契约联调 → API 使用 → 文档维护”排列；设计目录先读责任索引，Run 链按“创建 → 资源准备 → Runtime → 执行监督 → 预算”排列。调整顺序不扩大内容扫描范围，不需要把业务 Skill 原文加入索引。

身份链按“认证与会话 → 登录入口防护 → 用户生命周期 → 外部 Secret”排列。用户管理保留认证页旧章节的短跳转；浏览时须能从代码 README、目标接口、失败界面与当前状态互相转到正本，不因已有内部代码就把设计页标成操作手册。

领域模型之后先放项目生命周期，再进入上述身份链。Project 的归档/成员/删除有独立责任，既不埋进账户密码协议，也不在领域模型里维护第二套失败矩阵。项目入口必须同时说明已实现行为与失效链接、并发及引用遗漏等修正要求。

项目生命周期后安排文档资产，从保存/删除的具体例子进入跨存储边界；Run 链仍使用原资源快照页。工程 README 的资产管理入口与文档选择入口分开，搜索文件名、双向链接和章节刷新都应能进入各自正本。

Run 链在 Runtime 后安排“用户答复、等待与续行”和“结果、证据与人工评价”，再读停止和预算。Runtime §8 / §10 与 Workspace §7.3 保留旧编号入口，普通答复页负责期限，结果页负责原值和评价，外部批准仍回受控写入。不是把所有人工操作合并为一种恢复协议。

业务验收按“JAF 迁移与运行 → Benchmark 样本与评分”排列。旧验收页保留原编号跳转，新文档用本页主题组织，不继承原页的 10.x/12.x 编号；搜索同样能直接定位新的正本。

运维按“首次启动 → 发布与迁移 → 备份与恢复 → 症状 Runbook”排列。原 Runbook 的部署/恢复锚点仍能跳转，但现行 README/设计直接链接新正本。新页正文说明操作范围、失败停止和放行条件，不把真实故障注入写成只读检查。

文档工具回归覆盖失效链接/锚点（含浏览版深链接）、普通/引用/list 代码块闭合、中文标题与现行标题层级、离线导航链接、原始 HTML 不执行、嵌入范围与构建可复现性。它不需要启动应用或连接数据库；真实浏览器的焦点、布局与操作由下面的独立检查覆盖。

`--check` 执行相同检查并比较生成物是否与来源一致，内容未同步时退出非零，不修改文件。变更 Markdown 或浏览模板后重新 build，再提交/交付来源与 index.html。

### 可重复执行的浏览器检查

[check_docs_browser.py](../../PJM/scripts/check_docs_browser.py)直接打开生成的 file 页面，不需要 Web dev server。它默认不写文件，并在浏览器尝试访问 HTTP(S) 时阻断请求、令检查失败，确保浏览版没有引入 CDN 或 API 依赖。

首次在 `PJM/` 安装浏览器验证依赖，复用现有锁定版本；这不是安装业务 Web 或启动应用：

```bash
python3 -m pip install --user -r web/tests/browser/requirements.txt
python3 -m playwright install chromium
PYTHONDONTWRITEBYTECODE=1 python3 scripts/check_docs_browser.py
```

首次依赖/Chromium 安装需要下载；已经安装后，文档检查本身离线运行。依赖和浏览器外置时分别用 PYTHONPATH 与 PLAYWRIGHT_BROWSERS_PATH 指向已有目录，不创建 venv。`--output <明确的截图目录>` 会创建目录并覆盖脚本定义的固定名称截图，建议使用新的工作区外目录；不指定时不保存截图。具体生成数量记在当轮验证记录，不在多个 README 重复维护。

#### 按改动选择验证范围

| 改动 | 最低检查与补充条件 |
| --- | --- |
| 正文、链接或示例 | 全书 build/check、文档 unittest、相关契约；桌面和手机检查修改章节及入口的实际点击 |
| 新页、标题或阅读路径 | 上项 + 新旧锚点、搜索命中、深链接原生刷新；同步 SECTION_TARGETS 与相关 handoff 检查 |
| viewer 样式、导航或搜索 | 全量浏览器脚本：全部页面布局、全部关键章节和全部阅读路径；不能只验一页 |
| 补录验证结果 | 重新 build/check，复查新增文字/链接及原锚点；不把补录前的截图当成最终文字的证据 |

现有 CLI 默认运行全量，没有按章节筛选的 option；不要编造 `--section` 等参数。临时定点检查可在工作区外复用脚本函数，但必须记录具体页面、宽度、字号和点击路径，并明确未执行全量。每轮的件数、截图和失败原因只记 history，不追加到本指南。

#### 自动检查各自证明什么

- 页面层：所有正文的桌面/窄屏布局与历史提示。
- 章节层：SECTION_TARGETS 的 320/390/768/1440px、16/24px 字号、标题焦点、原生刷新和恢复字号后的布局。H4 同样检查；不只验证 URL 正确。
- 导航层：首次入口、品牌/未知文档回退、搜索高亮/历史排除、重复点击、前进/后退、键盘菜单与打印。
- 交接层：从代码 README 真实点击到设计、契约、计划或排障入口。关键两列表须在手机默认字号同时读到含义和限制，不能隐藏一列获取通过。

具体 selector、锚点和操作序列以 [check_docs_browser.py](../../PJM/scripts/check_docs_browser.py) 的 SECTION_TARGETS 与 `check_*_handoff` 为准。下表仅帮助挑选受影响的阅读场景，不复制完整自动化步骤：

| 阅读场景 | 要让读者分清什么 |
| --- | --- |
| 初次阅读、Flow、Skill | 目的入口与设计责任；计划与执行事实、发布与就绪、业务内容与展示布局 |
| 输入与停止 | 逻辑/物理路径、准备/执行计时、取消意图/终态/进程退出；独立事务不画成原子提交 |
| 普通答复与续行 | REVIEW/批准/Evaluation、问题版本/Run 版本、原答复/当前状态、410/过期提交；旧 Runtime 入口和代码 README 能到新正本，未实现的确认状态不写成已可操作 |
| 结果与人工修订 | 技术终态/业务完整性/人工判断、引用格式/实际核验、原内容/响应包装层、原值/多条建议；旧 Runtime/Workspace 与代码入口能到正本，未知评价不自动重发 |
| 预算与子分析 | 分配/消耗/余额、内部状态/运行证明、子结果/主结果、Session/Tool 审计；限制与数字同时可见 |
| 外部效果与调度 | 批准/远端写入/回读/平台保存，规则/触发/Run，摘要/恢复账本和分页可见性 |
| 认证与 Secret | 登录配额/会话失效、等待/服务不可用、稳定值/换会话、协议切换/用户管理、认证/业务提交；外部密文与登录凭据分开 |
| 用户生命周期 | 内部用例/API/Schema/快照/Web 的接线边界、账号/ProjectMember、末位 ADMIN、锁后判定/提交、撤销行数/在线人数；密码错误/会话失效/结果未知以及旧章节到新正本 |

| 文档资产 | 目录/冻结清单、元数据/blob/副本、逐文件处理/整批提交、配额/实际占用、普通下载/冻结校验；保存与清理失败的限制同屏可见，不执行上传或删除命令 |

所有这些路径只浏览离线文档，不执行正文命令，不登录应用、创建测试 DB、启动模型、写入外部资源或运行生成代码。即使路径名含“批准”“轮换”“恢复”，也不是业务操作验收。

#### 深链接与截图判断

深链接以“文档 + 章节”为恢复目标，不保存任意段落的像素坐标。浏览版在首个 script 设置手动滚动恢复，避免刷新/前进后退时浏览器用旧布局坐标覆盖章节定位；依据为 [HTML History 规范](https://html.spec.whatwg.org/multipage/nav-history-apis.html#dom-history-scroll-restoration)。回归先检查原生 reload 的标题位置，再单独恢复放大字号检查布局，不能先调用 showPage 补位而掩盖刷新故障。另覆盖桌面切窄屏后直接刷新。

通过脚本仍须抽看截图确认阅读效果；自动检查不会评价设计是否合理，也不覆盖 ProjectMind 业务 UI、真实 DB 或模型。

### 人工浏览检查

在桌面和窄屏各打开一次 `docs/index.html`：从产品页进入计划/设计/代码入口；搜索正文术语并进入命中章节，再按 path 搜索；跳转章节、刷新深链接并前进/后退；用键盘操作导航。检查同一章节链接重复点击仍能回到标题，搜索包含 `<` 等字符时不被当成 HTML。桌面使用侧边章节目录，窄屏使用正文前的“本页内容”。

跳转后不仅确认标题获得焦点，还要确认完整标题位于固定顶部栏下方。对 320px 窄屏和放大文字再次检查；顶部栏换行后，章节滚动留白与弹出目录的起点应随实际高度调整。

顶部空间不足时允许分类和操作区分行，操作区的“Markdown 源文件”“目录”等标签保持完整，不挤成竖排碎字。浏览器检查同时验证标签单行、整页不溢出和动态顶部留白，不能通过隐藏操作按钮来获得通过。

长表格和结构图允许各自横向滚动，但整页不能被撑出屏幕。实际溢出的表格显示滚动提示，键盘可聚焦滚动区域。历史页应有明显提示，默认搜索不混入旧结论。浏览器验证说明布局和导航可用，不代表 ProjectMind 应用页面已通过验收。

简短数字比较使用 Markdown 的右对齐列（`---:`）；浏览版让这些列按内容收缩，不预留正文列的最小宽度。例如预算的已用/占用/可用应能在手机上同屏比较，不通过缩小全页字号或隐藏某一列来适配。长文字列仍保留可读宽度，真正复杂的表格仍允许局部滚动。
