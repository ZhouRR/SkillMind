# Skillmind 現在の進捗と改善方針

本ページは現在の能力、再確認待ち事項、改善の優先順位を管理する。開発の入口は[変更ガイド](../development/change-guide.md)、実行制約は[実行境界](../development/runtime-guide.md)を参照する。

## 現在の実行状態

コード評価基準：2026-10-16（配備済み画面とローカル実装済み能力を区別して記載）。**主要業務フローは実装済みであり、実業務実行と配備画面での受入確認を経ている。今後は実利用の結果に基づいて改善し、旧詳細設計リストに沿った進行は行わない。**

**実装済み**はコードと対応検証が存在すること、**再確認待ち**は目標環境や特定シナリオでの未確認、**必要時評価**は実需要が生じた時点で判断することを示す。未採用の拡張機能を分母にした進捗率は用いない。

## 実装済みの主要能力

| 範囲 | 現在の利用可能能力 | 検証境界 |
| --- | --- | --- |
| Skill → タスク | 取込・解析・公開・Project 有効化。複数 Skill フォルダから対象を選択し共有 Schema/参照を原 byte で固定。最小の入力/資源宣言と凍結原文で実行し、汎用 Tool は常備、操作許可は選択資源から固定。同一タスクで回答・継続 | 独立 Skill の取込〜実行・報告は実環境で確認済み。複数 Skill 選択と資源/Tool 分離は実装済み・配備後再確認待ち。解釈品質はユースケースごとに検証 |
| RV | Excel → Markdown 変換・保存 → レビュー → PostgreSQL/文書庫記録（FAIL 時のみレビュー報告書を保存） | 実業務経路を通過済み。原 byte への RV 付記追加、変換ファイル直渡と分割読取、静的書式解析（`excel-styles/v3`）、未完了記録の収束は配備後再確認待ち |
| デスクトップ試験 | RV 通過済み Markdown を直接用い、実行前に手順索引・元の期待値・環境を固定。MCP で起動・観測・段階操作し記録と結果を保存 | 既定 UI 手順の完走と結果保存を実環境で確認済み。`COMPLETED` は実行完了であり業務上の `PASS` ではない |
| 資源と外部書込 | 文書パス読書き、Git 編集ディレクトリとコミット提案、MCP 原生引数ファイル、PostgreSQL 原生 SQL、汎用 HTTP API（基底 URL 一覧と単発要求/応答交付）。資源ルーティング・権限・承認・回読検査を維持 | 旧 DB/文書/MCP 経路は実利用あり。原生クライアントと設定移行は隔離回帰済み・配備後再確認待ち。PostgreSQL は既存アカウント権限をそのまま利用 |
| 文書と実行履歴 | フォルダ管理、改名/移動、一括整理、検索・ソート、同名ファイルの既定上書き更新。20 MB 画像/テキスト preview、Worker 分割 Markdown と静的 Mermaid preview。履歴と文書の回収・復元・完全削除・最小監査 | 文書整理、preview/download、検索展開、空フォルダ検索は配備確認済み。分割 Markdown/Mermaid、Agent パス読書き、同名更新の旧版保持と競合復旧は配備後再確認待ち |
| ワークスペースとレポート | 待機中・進行中・タスク別の最新サマリ。詳細に結果・証拠・監査・評価・添付・所要時間を集約 | 主要画面、タブ、ダイアログ、バッジ整列、狭幅・双テーマは配備確認済み。履歴タスク名、版グループ化、添付折畳、三語表示改善は実装済み |
| 基盤管理 | ログイン/メンバー/Project、アーカイブ済み Project の完全削除、組織 API Key、接続資格情報、タスク検索と定期実行（毎日/毎週/cron、既定で自動承認し発火時の同意を固定） | Project 管理、API Key 作成/呼出/失効は実測済み。アーカイブ Project 完全削除、定期実行設定と自動承認権限回帰は実装済み・配備後再確認待ち |
| 実行効率と診断 | SQLSTATE 分類、テーブル構造再利用、凍結 Skill ファイル直渡、大ページ/JSON Pointer 精密読取、大回執のファイル交付、サマリ整形、監査エクスポート、保守キュー分離、所要時間観測 | 回帰と実所要時間の改善を確認済み。大ページ、回執ファイル交付、JSON 精密読取は隔離回帰済み、実業務での短縮効果は同条件で配備後再確認待ち |

デスクトップ実行と後続判定は凍結 Markdown・手順索引・元の期待値に基づき、受控 MCP 原 byte ダウンロード、モデル画像交付、Project 全文書庫読取、アップロード ID/hash 直読を接続済み。単回完走は無人安定性や欠陥検出率を保証しない。

## 継続確認事項

| 事項 | 現在の扱い |
| --- | --- |
| 業務結果の信頼性 | 固定入力・明確な範囲・独立した期待値で RV、実操作、結果保存、最終判定を照合し、漏れ・人工介入・未検証範囲を残す |
| 異常と復旧 | 取消、権限剥奪、再起動、競合、結果不明時は原操作と実配備環境で検証し、新規 Run 作成や書込再送で代替しない |
| 証拠の完全性 | Runner が返すパスは入庫済み証拠を意味しない。許可された能力で実ファイル取得と保存を確認し、未取得分は不足として明記する |
| データ整理と復元 | 参照保護と最小監査を維持。オブジェクト削除の永続リトライ/クォータ精算、インスタンス間復旧、Secret/データ復元は実配備で検証 |
| 継続的な性能 | 初回操作、人工介入、待機/再開、モデル出力、収束時間を比較。同一 job 内の自動承認後 Codex プロセス再利用、読取専用短ツール列、既定 OFF の単発 Effect 直接回執を実装済み（外部書込の一括列は未接続） |

共有予算の完全閉ループと確実な遠隔停止は未完。編集可能 Flow、生成 UI、子 Agent、高度オーケストレーション等は必要時評価とし、境界は[後置能力](../development/runtime-guide.md#後置能力)を参照する。

## 今後の進め方

1. **利用結果から課題を選ぶ**：再現手順と元 Run/画面を記録し、誤結果・データリスク・ブロッカーを最優先し、次に所要時間・反復操作・可読性を扱う。
2. **特定後に最小修正する**：Skill・モデル・プラットフォーム・外部サービス・画面を切り分け、[性能観測](../operations/run-performance.md)に基づき必要な保存・承認・回読・検証を省略せず修正する。
3. **回帰・配備・効果確認**：変更リスクに応じて検証し、凍結規則の変更で過去 Run を上書きしない。安定した規則変更のみガイドへ反映する。

## 交付判断

- **業務利用可能**：合意範囲を完了し、結論・証拠・記録・未実行項目を追跡可能で、実行完了と業務判定を分けて表示できる。
- **境界の非退行**：権限、凍結入力、承認、べき等性、参照保護、結果不明時の扱いが維持されている。
- **実配備可能**：関連回帰が通過し、目標環境で操作でき、残る制限と再確認待ちシナリオが明記されている。
