## 四层解耦与避免过度设计

- **先做四层归责再动手**：定位问题或新增能力时，必须先分清职责归属，严禁跨层打补丁：
  1. **业务知识库**：只放被测/目标系统的纯业务规则、画面、权限、数据与式样书表记，不混入 Skill、Agent、MCP 或工程流转指令。
  2. **业务 Skill（`SKILL.md`）**：以通用自然语言描述业务/测试流程、资源的确立（通过索引按阶段按需加载知识、区分管理记录与业务数据）和工具使用原则（大块读取、受控写入 `read_back` 确认执行器终态回执已记录而非预设操作必成功、结束前完成归档与终态更新），通过参照的 JSON Schema 定义核心交付契约；不耦合平台内部工具 ID、特定 MCP 实现或具体项目名称。
  3. **外部服务 / MCP 工具**：由服务自身通过 Tool Schema、配置与结构化错误码暴露能力与约束。
  4. **平台底座**：提供通用文件/数据库/转换/Schema/受控写入通道与安全隔离，不内嵌具体业务表结构或项目专用分支。
- **破除历史包袱（做减法而非叠禁令）**：架构、契约或 Skill 演进后，直接用正向语言陈述“当前应该怎么做”，主动删掉针对已废弃方案（如旧中间文件、旧计划字段、旧流程）的“禁止做某某旧操作”防御性否定句；不把单次运行的偶发故障或特定环境数据固化为全局复杂规则。
- **最小可用改动**：以本次用户场景为终点，不为假设中的扩展新建抽象层或配置；验证范围与改动相称，保留权限、数据保护、失败停止及可定位错误，不顺手重构无关模块。

## 防止文档膨胀

- 稳定规则变化才原位更新正本，功能状态只改 roadmap 对应项；不追加交付日志、测试次数、临时路径或命令输出。
- README 做导航，AGENTS 留必需约束，Skill 留通用工作流。引用既有契约/操作指南，默认不建模块 README、历史页或重复 references。
- 精简重复与过时兼容表述，保持权限、冻结、批准、事务/结果未知边界清晰；标题/路径变化同步引用。

## 验证与收尾

- 遵守 AGENTS 的修改/授权边界，按开发指南选择本次检查并报告实际证据；先核实环境，不固化 Git/Docker 可用性等临时状态。
- 不建 venv，优先复用依赖；Python 检查用 PYTHONDONTWRITEBYTECODE=1，外置依赖用 PYTHONPATH。只清理本次创建且目标已确认的临时物，保留已有成果；不以删后重建绕过权限拒绝。
- 文档构建/浏览按维护正本执行，不手改 HTML。仅改本 Skill 时验证格式、引用和决策边界；浏览版未受影响就不重建，也不追加计划记录。
- Skill 更新只处理指定包，不自动同步安装副本或其他执行资产；system Interpreter 的版本/hash 同步要求见实现细则，不套用于本开发 Skill。
